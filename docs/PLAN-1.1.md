## 版本目標

簡化父親日常使用的主頁，讓輸出格式直接可見，補齊 USB 歌曲管理，固定更新來源，並縮小手機安裝包。

版本為 **1.1.0**，`versionCode = 2`。採用新套件名稱 **`com.kgm2mp3_usb.app`**，已生成獨立的新簽名金鑰；後續新版沿用這個套件名稱與新簽名。最低 Android 8（API 26）；手機正式版使用 arm64-v8a。

你提供的 `com.kgm2mp3-usb.app` 是套件名稱，不是簽名憑證；其中連字號不符合 Android applicationId 規則，規劃改為底線 `com.kgm2mp3_usb.app`。套件名稱與簽名都更換後，1.1 作為新 App 手動安裝，可與 1.0 共存，不能直接覆蓋 1.0；首次需重新設定及授權。參考 [Android 官方套件名稱規則](https://developer.android.com/build/configure-app-module#application-id)。

- 「设置 → 选择 USB 根目录」保留。
- USB 未選定時，USB 空白頁提供「选择 USB」。
- 手機已有勾選歌曲但 USB 未就緒時，點「转移」引導選擇 USB；未發現装置時提示插入 U 盤。
- 「转移」只在手機分頁顯示，來源只使用手機的勾選歌曲。USB 分頁以刪除操作為主。
- 處理期間暫停修改格式、目錄及目標裝置；進度、取消、結果和重試繼續可見。
- 按鈕觸控區維持至少 48 dp，驗證較小螢幕和放大字體，必要時讓 USB 工具列換行。

## 三、USB 多選與刪除規則

USB 歌曲只允許逐首勾選，不提供「全選／取消全選」按鈕，也不提供一次勾選全部歌曲的其他入口。手機歌曲分頁的全選功能保留。

手機和 USB 使用兩組獨立選擇。切換分頁可保留各自勾選；USB 選擇另綁定裝置 ID。切換 USB、拔出或授權失效時清除 USB 勾選；刷新只保留仍存在且未變動的項目。

未勾選時「删除」禁用。點擊後顯示一次確認：

> 删除 USB 中选中的 N 首歌曲？  
> 手机歌曲会保留，删除后无法撤销。  
> [取消] [删除]

確認後固定本次目標裝置與歌曲清單：

1. 每首刪除前重新確認目標仍掛載，且檔案是該 USB 根目錄的普通音樂檔案。
2. 直接路徑驗證實際父目錄；SAF 從已授權根目錄重新列舉並匹配精確 URI。
3. 檔名、大小或修改時間已變動的歌曲跳過，提示重新選擇。
4. 轉移與刪除互斥。刪除在背景執行，畫面重建不能重複發起。
5. USB 拔出立即停止餘下操作；取消只停止尚未刪除的歌曲。
6. 完成後刷新 USB 列表和剩餘空間，顯示「已删除 N 首，未删除 M 首」及失敗原因。
7. 程序中斷後重新掃描，由使用者重新選擇；不自動續刪。

刪除範圍不包含手機歌曲、子資料夾及其他檔案。手機原檔保留、轉移同名覆蓋的既有規則繼續適用，相關說明保留在設定／使用說明中。

## 六、48 MB 的原因與瘦身方案

對 1.0 正式 APK 的 ZIP 內容實測：

| 部分 | APK 中大小 |
|---|---:|
| arm64-v8a 原生音訊庫 | 21.33 MB |
| x86_64 原生音訊庫 | 24.68 MB |
| 壓縮後 Java／Kotlin 程式碼 | 1.78 MB |
| 其他資源與許可文件 | 0.26 MB |
| ZIP、簽名和對齊開銷 | 0.17 MB |
| 合計 | **48.22 MB** |

原始檔案為 **48,219,532 bytes**（45.99 MiB）。**95.42% 是音訊原生庫**；KGM 核心 JAR 只有約 27 KB。

主要體積來自內置離線 FFmpeg 轉碼功能，以及同一 APK 內放了兩種 CPU 架構。第一版選用了完整的現成音訊構建，且原生庫未壓縮，以便直接從 APK 載入。畫面數量少，不能直接推算這些原生功能的體積。

你提到的 TiebaLite 小於 10 MB，可以作為體積期待；目前未拆解你使用的那個 APK，不能把它的內部依賴當成已知。這個軟件目前的實測瓶頸已明確集中在音訊庫與雙架構打包。

### 1.1 採用：分開架構

正式手機包已只保留 arm64-v8a，移除 x86_64 內容。最終簽名 APK 實測 **23,484,946 bytes（23.48 MB）**，較 1.0 的 48.22 MB 縮小約 **51%**，已低於 25 MB 目標。最終 APK SHA-256 為 `6a62e3c3cbf9bb61567e9992078d3d057c9467e61aab02d97c7406f380ff9c41`；22 項 Android 功能回歸於圖示修改前的基線包完成。本輪僅圖示資源微調，DEX 與 10 個原生庫字節內容不變，並重新完成構建、簽名／對齊、安裝與桌面圖示核對。

保留現有轉碼構建與 16 KB 對齊。R8／資源裁剪可作為次要優化候選，須保留 JNI 必要類並驗證正式包的原生啟動及四格式轉換；主要收益仍來自分架構。

### 可選：壓縮原生庫

按現有 ARM64 庫在記憶體內試算 DEFLATE，壓縮打包可能約 **12.5–13 MB**。這不是已構建的 APK。

壓縮後安裝時需解壓原生庫，APK 加解壓庫的估算約 33.8 MB，另有一般程式資料；下載檔變小，安裝占用會增加。1.1 預設先採分架構、維持直接載入的方案。

[Android 官方文件：原生庫壓縮與安裝占用](https://developer.android.com/guide/practices/page-sizes)

### 後續精簡內核

若目標是低於 10 MB，需要研究自行編譯精簡 FFmpeg，保留實際用到的音訊格式、MP3 編碼、完整解碼驗證、PCM 摘要與 FLAC 恢復流程。不能直接刪除相互依賴的原生庫。

此項列為後續版本研究；先完成所有格式與裝置回歸，再確認可達體積。這次 1.1 不預先承諾低於 10 MB。
